## 1. 产品目标与技术约束

以 Python 3.13 和 `pygame-ce`（代码中 `import pygame`）开发 Windows 桌面箭头解谜游戏。首要目标是规则正确、操作直观、中文清晰、运行稳定，代码结构适合课程展示与讲解。

最终交付源码、依赖清单、Windows EXE、README、项目截图、演示 GIF、测试报告、真实 AI 协作记录及课程博客 Markdown 草稿。不得将自动化验证写成本人试玩，不得编造工时或开发过程。

界面采用纯黑背景（#000000）、深灰圆角面板和浅紫主色；提示使用暖金色，碰撞使用亮莓红色，四方向继续用不同颜色区分。该方案由用户在完整版本完成后明确要求改为黑色背景，并保留“配色和参考不要一样”的约束。默认窗口为 960 × 800，支持缩放，并同步变换绘图与鼠标坐标，保持操作位置准确。箭头、按钮和背景使用程序绘制；随项目提供可分发中文字体与许可信息。

用户允许在需要插画或背景素材时使用88API。本阶段不需要生成图像，所有预览图均由Pygame直接绘制。

## 2. 规则与状态

| 编号 | 必须实现的行为 | 验收方式 |
|---|---|---|
| R01 | 棋盘为二维网格；每格为空，或仅有一个上、下、左、右箭头 | 检查关卡数据及四方向绘制 |
| R02 | 左键点击箭头后，从其正前方相邻格沿朝向逐格检查到边界 | 检查四方向的相邻与隔空案例 |
| R03 | 正前方整段路径上只要有任意方向的箭头即阻挡；身后或其他行列的箭头不阻挡 | 用不同阻挡距离及朝向的测试局面验证 |
| R04 | 无阻挡时播放约 0.3 秒飞出动画；动画结束才消除并更新剩余数量 | 对照动画前、中、后的棋盘状态 |
| R05 | 受阻时播放约 0.25 秒前冲回弹、闪红并突出最近阻挡者；每次动作仅扣 1 次失误机会 | 连点同一受阻箭头，观察扣次与高亮 |
| R06 | 点击空格、棋盘外、已消除位置，或使用右键，都不触发动作、不扣机会 | 覆盖无效输入案例 |
| R07 | 动画期间只执行一个棋盘动作，忽略重复棋盘点击；重开、静音及关闭仍有效 | 连点、动画中重开与关闭窗口 |
| R08 | 每次挑战初始有 3 次失误机会；最后一次碰撞反馈结束后进入失败 | 连续 3 次有效受阻操作 |
| R09 | 清空棋盘后进入通关结果，玩家主动点击下一关；最后一关显示全部完成 | 用可解顺序完成单关及第六关 |
| R10 | 重开复制本关原始布局，恢复 3 次失误和 3 次提示，并取消旧动画 | 中途、失败后及动画中重开 |
| R11 | 结果页出现后底层棋盘不响应输入 | 在结果页点击棋盘位置 |
| R12 | 动画按经过时间推进，不使用阻塞等待；窗口保持响应 | 不同帧率、拖动及关闭窗口检查 |

状态至少包含首页、选关、游戏、动作动画、单关通关、失败、全部通关。原始关卡布局不可变，每次开局或重开使用副本。规则与 Pygame 界面分离，路径检测、可消除箭头查询、可解性验证和状态推进可以独立验证。

## 3. 页面与流程

### 首页

显示游戏名称、简短规则、“开始游戏”“关卡选择”和声音开关。“开始游戏”进入当前尚未完成的最前关卡；全部完成后从第一关开始。

### 选关页

以 6 张卡片展示关卡名称、难度、锁定或完成状态，以及已完成关卡的最佳成绩。首次运行只解锁第一关；通过一关解锁下一关，已解锁关卡可重复挑战。

### 游戏页

- 顶部：当前关卡、剩余箭头、剩余失误机会。
- 中央：清晰的棋盘与四方向箭头，鼠标悬停时高亮目标箭头。
- 底部：提示、重新开始、返回选关按钮，以及简短反馈文字。
- 全局：声音开关；用图形和数字表达状态，避免仅靠颜色辨认。

返回选关或关闭游戏即结束当前未完成挑战，不保存未完成棋盘。

### 结果页

| 结果 | 显示信息 | 可用操作 |
|---|---|---|
| 单关通关 | 通关信息、本次失误数、本次提示使用数 | 下一关、重玩本关、返回选关 |
| 失败 | 失误机会耗尽 | 重玩本关、返回选关 |
| 第六关通关 | 全部完成、本次成绩 | 从第一关重玩、返回选关 |

## 4. 六个固定关卡

| 关卡 | 名称 | 尺寸 | 难度 | 教学或挑战重点 |
|---|---|---|---|---|
| 1 | 初识箭序 | 5 × 5 | 入门 | 点击、边缘飞出与简单阻挡 |
| 2 | 留意空隙 | 5 × 5 | 入门 | 隔着空格也会形成阻挡 |
| 3 | 交错之间 | 6 × 6 | 进阶 | 横向与纵向依赖交错 |
| 4 | 逐一解锁 | 6 × 6 | 进阶 | 连续解除多层阻挡 |
| 5 | 四向交织 | 7 × 7 | 挑战 | 更高密度与更长依赖关系 |
| 6 | 最后之序 | 7 × 7 | 挑战 | 综合观察与消除顺序 |

每关均包含四种方向，整体上逐步增加箭头密度与阻挡依赖。最终布局须通过独立的可解性检查，保存合法通关顺序，再由用户本人实际试玩全部六关。

只删除箭头不会产生新阻挡，因此求解器可以反复寻找当前可消除箭头并删除；如果剩余箭头非空而无可消除箭头，则该布局未通过验证。求解器同时支持游戏页的“自动求解”按钮，按钮按合法顺序逐支播放飞出动画；自动求解期间忽略棋盘点击，但保留重开、返回和静音操作。

## 5. 提示、成绩、存档与音效

| 功能 | 约定 |
|---|---|
| 提示 | 每次挑战 3 次；高亮一个当前可消除箭头，不代替点击。高亮仍有效时重复点击提示不再扣次；动画或结果状态不触发新提示 |
| 成绩 | 仅完成关卡后记成绩。先比较失误次数，再比较提示使用次数，越少越好；同成绩无需重复替换 |
| 存档 | 本地保存解锁进度、各关最佳成绩及静音设置，不保存未完成棋盘 |
| 存档异常 | 损坏时恢复默认数据并提示；保存失败时仍可继续游戏，告知本次进度未保存 |
| 重开 | 恢复原始布局及全部机会，清除提示高亮与未完成动画 |
| 音效 | 提供点击、飞出、碰撞、通关或失败音效；可静音；音频设备不可用时自动静音运行 |

首版不包含撤销、计时挑战；当前版本已经加入自动求解按钮、随机关卡、星级评价和背景音乐。

## 7. 三个阶段与确认节点

1. **需求与界面预览**：形成本文、PSP 预计耗时与过程记录，制作首页、游戏页和结果页预览。**确认节点 1：用户确认配色、布局、箭头大小与文字清晰度，再推进完整实现。**
2. **完整游戏**：实现规则、六关、动画、流程、提示、选关、存档、音效，先完成自动测试和画面检查。**确认节点 2：用户本人试玩全部六关，确认难度、手感及功能，依据反馈修正。**
3. **打包与作业材料**：整理源码、EXE、README、测试报告、真实 AI 记录、截图、GIF 和博客草稿。**确认节点 3：用户审阅最终游戏与材料，补齐学号、个人体验和 GitHub 目标仓库，再安排上传。**
